01 / Ringkasan pilihan

Hosting yang sesuai.
Biaya yang jelas.

Opsi deployment website sewa, aplikasi pelanggan, dan panel admin iRent. Dokumen ini menjadi bahan memilih layanan; belum ada pembelian atau deployment produksi.

Rekomendasi: VPS + satu domain .com

Jalankan frontend, API, PostgreSQL, dan worker pada satu VPS terlebih dahulu. Pilih kapasitas menurut anggaran; target awal 2 vCPU dan RAM 4–8 GB memberi ruang lebih nyaman. Ini perkiraan engineering, belum hasil uji beban produksi.

Apa yang sebenarnya kita hosting?

WEBSITE & PWA

Halaman pelanggan dan admin

Frontend React/Vite berupa hasil build statis. Aset ini relatif mudah ditempatkan di hosting yang menyediakan HTTPS dan pengaturan route.

API & WORKER

Proses bisnis yang terus aktif

Backend NestJS/Node.js menjalankan booking, pembayaran, tenggat, dan pengingat. Proses server perlu tetap berjalan, termasuk saat tidak ada pengunjung.

DATABASE

PostgreSQL

Alokasi stok dan transaksi bergantung pada transaksi database, locking, serta aturan yang sudah dibangun untuk PostgreSQL. Mengganti ke MySQL bukan sekadar mengubah konfigurasi.

FILE & BACKUP

Penyimpanan persisten

Foto item dan bukti pembayaran harus bertahan saat aplikasi diperbarui. Bukti privat dilayani melalui otorisasi API; backup perlu disalin ke luar server utama.

Internet → domain + HTTPS → frontend / API → PostgreSQL & file persisten
Worker memproses tenggat dan pengingat di sisi server.

Dasar kebutuhan: backend/package.json, backend/.env.example, frontend/package.json, dan PRD repository iRent saat dokumen disusun. Tidak memerlukan Redis sebagai syarat deployment implementasi saat ini.

02 / Shared hosting

Kenapa tidak langsung
pakai shared hosting?

Bisa untuk bagian frontend. Untuk menjalankan seluruh iRent, paketnya harus memenuhi kebutuhan backend dan database, bukan hanya bisa membuka file website.

Kebutuhan iRentYang harus diperiksa pada shared hosting
Backend Node.jsDukungan versi Node yang sesuai manifest: backend saat ini Node 24.15–24.x; fitur aplikasi Node, restart otomatis, dan proses yang tetap aktif.
PostgreSQLTersedia PostgreSQL yang kompatibel, koneksi dan izin migrasi Prisma, serta dukungan transaksi/locking. Paket MySQL saja tidak memenuhi kebutuhan.
Worker pengingatProses latar belakang boleh berjalan terus dan tidak diputus oleh kebijakan idle/resource. Adanya cron saja belum membuktikan worker saat ini bisa berjalan.
Upload privatDirektori persisten terpisah dari file publik, batas upload yang sesuai, akses tulis, serta mekanisme backup dan pemulihan.
Deployment & PWAHTTPS, environment rahasia, route SPA/API, serta manifest dan service worker dilayani dengan benar. Koneksi keluar untuk Web Push harus diizinkan.

Contoh keterbatasan yang nyata

Dokumentasi Hostinger menyatakan PostgreSQL tidak tersedia pada paket Web/Cloud yang dibahas di halaman dukungannya dan mengarahkan pengguna ke VPS. Ini contoh spesifik provider, bukan aturan untuk seluruh shared hosting. [S3]

Kapan shared hosting tetap masuk akal?

  • Frontend saja: hasil build React ditempatkan di shared hosting; API dan database tetap di layanan lain. Ada tambahan konfigurasi proxy atau cookie/CORS bila berbeda origin.
  • Paket khusus aplikasi: provider mengonfirmasi seluruh persyaratan di atas. Label “Node.js supported” saja belum cukup untuk memutuskan.
  • Website informasi sederhana: bila hanya beranda/katalog statis tanpa operasional sewa, kebutuhan hosting jauh lebih ringan.

Pilihan untuk iRent: VPS lebih mudah disesuaikan dengan implementasi sekarang. Shared hosting bisa dievaluasi jika ada paket konkret yang memenuhi persyaratan; kita tidak perlu mengganti arsitektur bisnis demi paket yang kurang cocok.

04 / Setelah memilih layanan

Siap tayang.
Lalu mudah ditemukan.

Hosting dan domain membuat situs bisa diakses. Untuk mendatangkan pelanggan dari pencarian, perlu pekerjaan SEO dan profil bisnis secara terpisah.

Google Maps / Profil Bisnis

Verifikasi bisnis yang memenuhi syarat, isi alamat atau area layanan secara akurat, jam buka, foto asli, dan kontak. Dorong ulasan jujur dari pelanggan. Peringkat lokal dipengaruhi relevansi, jarak, dan popularitas. [S5]

Pencarian organik website

Siapkan halaman sewa iPhone Semarang yang informatif, harga, syarat dan detail perangkat; judul unik, sitemap dan Search Console. Google tidak menjamin posisi pertama atau pengindeksan. [S6]

Untuk React/Vite, evaluasi prerender halaman publik agar konten utama tersedia sebagai HTML. Halaman akun/admin tidak ditargetkan untuk pencarian; otorisasi server tetap melindungi data. [S7] Google Ads dapat menambah visibilitas berbayar; posisi tetap mengikuti lelang dan kualitas. [S8]

Urutan eksekusi yang disarankan

01
Pilih anggaran, provider dan lokasi server yang tersedia; cek latensi dari Semarang, kontrak, pajak, perpanjangan, serta ketersediaan domain.
02
Siapkan server, DNS, HTTPS, Node yang kompatibel, PostgreSQL, secret produksi dan penyimpanan persisten. Aktifkan worker dan konfigurasi VAPID.
03
Deploy build dan migrasi; buat admin, isi data riil, uji booking sampai return/refund, PWA dan push perangkat fisik. Aktifkan monitoring, backup eksternal dan uji restore.
04
Publikasikan setelah pemeriksaan selesai; daftarkan Search Console dan Profil Bisnis. Ukur trafik, konversi booking dan beban server sebelum menaikkan paket.
